# Recommended University Defense Demo

## 8–12 Minute Demonstration Flow

### 1. State the exact task (30–45 s)

Say:

> “The project performs window-level multi-label environmental audio tagging. It predicts which trained sound classes are present in each short window; it does not estimate exact onset/offset times.”

This immediately prevents confusion with full SED.

### 2. Show the architecture (60 s)

Use the pipeline from `docs/ARCHITECTURE.md`:

```text
Audio -> window -> Log-Mel -> CNN or CNN+GRU -> sigmoid -> per-class thresholds
```

Emphasize that CNN and CRNN use the same data split and preprocessing.

### 3. Show the data protocol (60 s)

Open `config/default.yaml` and explain:
- 8 target classes,
- 2 held-out classes,
- folds 1–7 / 8 / 9–10,
- mixtures are generated only after the split is fixed,
- relative dB and overlap are explicit experimental factors.

### 4. Show leakage protection (30 s)

Run or show:

```bash
python scripts/prepare_urbansound8k.py ...
```

Point to `Leakage check: PASSED`.

### 5. Demonstrate the local UI (2 min)

```bash
python scripts/run_ui.py \
  --checkpoint <final-model> \
  --thresholds <final-thresholds>
```

Upload a known example and one mixture/recording. Show:
- multiple simultaneous labels,
- individual scores,
- score timeline,
- compute time.

### 6. Demonstrate the research comparison (2–3 min)

Show the final aggregated table generated by `scripts/summarize_experiments.py`.

Discuss:
- CNN vs CRNN mean ± std,
- parameter counts,
- relative-level groups,
- overlap groups,
- runtime trade-off.

Do not claim CRNN is better unless the actual final data supports it.

### 7. Demonstrate runtime (45 s)

Show `runtime.json` and explain:

```text
p95 compute time < 1 s hop
```

Then distinguish this from initial two-second window-formation latency.

### 8. End with limitations (45 s)

Explicitly mention:
- UrbanSound8K starts as single-label,
- synthetic mixtures are not identical to real soundscapes,
- threshold rejection is not general open-set recognition,
- exact event boundaries are outside scope.

## Technical Questions Likely to Be Asked

### Why not Softmax?

Because labels are independent and multiple classes may be active; sigmoid + BCEWithLogitsLoss is appropriate.

### Why is test never used for threshold tuning?

Using test for threshold choice would leak evaluation information and invalidate the final metrics.

### Why use GRU?

It adds within-window temporal modeling with fewer parameters than an equivalent LSTM, keeping the model lightweight.

### How is overlap different from relative dB?

Overlap controls how much of the second source exists temporally inside the window; relative dB controls source amplitude. They are evaluated separately.

### Is `no_confident_known_class` an unknown detector?

No. It only states that no trained class passed its selected threshold. It cannot reliably identify an unknown component that co-occurs with a known source.

### What makes the experiment reproducible?

Frozen classes/folds, deterministic manifests, fixed seeds, saved configs/checkpoints/thresholds, same preprocessing, and an untouched test split.
