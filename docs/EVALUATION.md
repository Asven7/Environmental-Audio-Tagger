# Evaluation Protocol

## Research Question Alignment

### RQ1 — CNN vs CRNN

Run both models under identical:
- source splits,
- target classes,
- preprocessing,
- mixture manifests,
- optimizer family,
- metrics.

Final comparison should aggregate at least three fixed seeds.

### RQ2 — Relative Source Level

Two-source mixtures are tagged with explicit `relative_db` metadata. The evaluator reports grouped results for each configured level, defaulting to `-6, 0, +6 dB`.

Positive dB means the first source is louder than the second under the repository’s mixing convention.

### RQ3 — Temporal Overlap

Two-source mixtures are tagged with explicit `overlap_ratio`. Default real-data configuration uses `0.25, 0.5, 1.0`.

The second source is shifted within the fixed output window so only the configured fraction remains in the window.

### RQ4 — Compute Cost

Report:
- trainable parameter count,
- feature extraction time,
- model inference time,
- total compute time,
- p95 total compute time.

The engineering no-backlog criterion is:

```text
p95(total window compute time) < hop duration
```

This does not remove initial latency caused by collecting the first window.

### RQ5 — Limited Held-Out Rejection

Known-class thresholds are tuned on known validation data. Held-out validation examples can be inspected for rejection behavior without changing test data.

Test report:
- OOD rejected recall,
- OOD false acceptance rate,
- known false rejection rate.

This is explicitly **not** a complete open-set recognition evaluation.

## Metrics

### Multi-Label Metrics

- Precision (micro, macro)
- Recall (micro, macro)
- F1 (micro, macro)
- mAP
- Hamming Loss
- per-class Precision/Recall/F1/AP

Accuracy is intentionally not the primary metric.

## Threshold Selection

For each class independently:

1. evaluate a fixed configured threshold grid,
2. calculate binary F1 on known validation samples,
3. select maximum F1,
4. tie-break toward 0.5,
5. save the selected threshold,
6. never alter it after test evaluation begins.

## Repetition

Final research claims should use all configured seeds (`13, 23, 37` by default) and report mean ± standard deviation.

The synthetic demo configuration uses only one seed because it exists only as a smoke test.

## Real-World Validation

A small independently recorded/annotated multi-label set is recommended but is data-dependent and is not fabricated by this repository.

If added:
- define recording device/environment,
- obtain permission for recordings,
- avoid storing unnecessary speech,
- annotate window-level class presence before looking at model predictions,
- report its results separately from UrbanSound8K-derived controlled mixtures.

## What Not to Claim

Do not claim:
- exact event timing,
- real-world production accuracy from synthetic mixtures,
- general unknown-sound recognition,
- superiority of CRNN before multi-seed real-data evaluation,
- any performance number not generated by the provided evaluation code on a documented dataset split.
